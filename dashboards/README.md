## How to Use These Dashboards

1. **For product strategy meetings**: Share with product team, stakeholders to align on decisions
2. **For design handoff**: Reference the design decision cards and accessibility/motion requirements
3. **For research planning**: Use risk/mitigation sections to identify validation gaps
4. **For competitive positioning**: Compare against ExamSoft, Canvas, D2L feature tables

## Dashboard Architecture

Every dashboard follows the same structure:

1. **Overview**: Product phase, readiness metrics, key dates
2. **Strategic Analysis**: Competitive positioning, architectural decisions, design choices
3. **Granola Synthesis**: Latest insights from team meetings and stakeholder interviews
4. **Timeline**: Roadmap phases with deadlines
5. **Risks & Mitigation**: Known blockers and contingency plans
6. **Success Metrics**: Measurable KPIs for product validation

## Behind the Dashboards

All dashboards are built from:

- **Granola sessions** (15+ per product): Strategic meetings, design reviews, stakeholder alignment
- **Competitive research**: ExamSoft, Canvas, D2L, Anthology feature comparison
- **Design decisions**: Documented tradeoffs and architectural rationale
- **User research**: Student, faculty, SCCE, Program Director interviews and signals
- **Accreditation context**: CAPTE, ACOTE, CCNE, ARC-PA requirements and compliance risks

See `SKILL_v5_0_0.md` for the full 8-perspective research architecture.

## Adding New Dashboards

1. Create new HTML file in this folder
2. Follow the same structure: overview → strategy → insights → timeline → risks → metrics
3. Include a "Why:" rationale for every chart and data table
4. Reference Granola sessions and sources
5. Update this README
